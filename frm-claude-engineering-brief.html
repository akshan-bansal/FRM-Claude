What this is

An end-to-end retail trading stack for Questrade: market data in, strategy signals out, risk gates in between, orders placed against either an in-memory paper book or the real brokerage. Paper mode is the default and live mode is deliberately awkward to reach.

Roughly 3,650 lines of Python across 43 modules, plus about 1,160 lines of Claude Code scaffolding — seven skills, fourteen slash commands, three subagents, and a SessionStart hook. The agent scaffolding is not decoration: it is a real part of the safety model, and it is where some of the strongest and weakest guarantees live.

Stack: Python 3.13 on uv, typer CLI, pydantic v2 at every boundary, httpx for HTTP, structlog for logging, pandas/numpy for vectorized signals, pytest + respx for tests with no live calls.

Two ways to trade, one way to execute

The repo supports a Claude-driven trader (Claude reads state, decides, and calls trading place-order) and a deterministic background daemon (autonomous run polls and decides on its own). They are genuinely different decision-makers, but they share the same router, the same gates, and the same journal. Neither can reach a broker another way.

The spine: one chokepoint

Router.submit() at execution/router.py:221 is the only code path that calls broker.place_order(). Strategies return DataFrames; they hold no broker reference and cannot place anything. Every intent is journaled before dispatch, accepted or not.

All eight gates are evaluated on every submit; reasons accumulate rather than short-circuit, so a rejection reports every failure at once.

Three independent safety layers

The design worth admiring here is that the safety story does not rest on any single mechanism. Three layers sit in series, each enforced by a different system.

Harness
Claude cannot run the dangerous commands at all. .claude/settings.json denies trading live, autonomous run, and clear-kill, plus reads of .env and state/tokens.json. Enforced before Python starts.
Python
The type system refuses unconfirmed live routers. Live mode needs an exact typed phrase; autonomous mode needs an environment sentinel read fresh on every construction, deliberately never cached.
Runtime
A file stops everything. touch state/HALTED from any shell blocks every subsequent order; the router re-reads it on each submit. Clearing it requires the literal ack I HAVE INVESTIGATED, and Claude is denied the clear command outright.

One more quiet but real protection: _load_trading_yaml() filters incoming YAML against an explicit allowlist of non-secret knobs, so even a hostile config/trading.yaml cannot inject a refresh token or encryption key. Secrets have exactly one source.

Findings

Eight things worth knowing, verified against the code rather than the documentation. The first three change behaviour; the rest are drift and hygiene.

The kill-switch never trips itself

Behavioural

KillSwitch.evaluate() contains the automatic trip logic — equity wipeout, max drawdown, daily loss limit — and it has zero production call sites. Only tests invoke it. Both max_drawdown_kill_switch (10%) and daily_loss_limit_pct (3%) are threaded dutifully into the constructor, but the method that reads them is never called by the daemon or the live loop.

The practical effect: the kill-switch is a manual instrument only. Nothing halts an autonomous session that is quietly drawing down. A human trip still works well — the router re-reads the sentinel on every submit, so trading kill stops new orders on the next iteration.

Evidence grep for .evaluate( across src/ and tests/ returns two hits, both in tests/test_risk.py. monitor/live_loop.py and cli.py:autonomous_run check state() only.

The autonomous flags Claude must not flip are reachable through a file Claude can write

Policy gap

CLAUDE.md lists flipping AUTONOMOUS_ENABLED and AUTONOMOUS_ACCOUNT under "what Claude is NOT allowed to do", framing both as .env values the human owns. But both are members of _TRADING_KNOB_FIELDS, which means config/trading.yaml can set them — and YAML is passed to Settings(**yaml_data) as init kwargs, which outrank both environment variables and .env in pydantic-settings. That file is explicitly Write- and Edit-allowed in settings.json.

The allowed command pattern Bash(uv run trading autonomous start:*) also covers --account live via its wildcard, and autonomous start injects AUTONOMOUS_ENABLED=true into the child process itself — satisfying the router's sentinel check. So the chain closes through permitted actions only: the policy is enforced by instruction, not by the permission system.

The hard stop for real money does hold: live trading still needs a refresh token and encryption key from .env, which Claude genuinely cannot read or write. Practice-account autonomous trading, however, is reachable. Worth noting too that the refusal message reads "AUTONOMOUS_ENABLED is false in .env", which names the wrong source — YAML is the one that wins.

Evidence config/settings.py:111-137 (allowlist includes both flags) · cli.py:470 (gate reads settings.autonomous_enabled) · cli.py:485-488 (injects the sentinel) · .claude/settings.json (YAML writable, start:* allowed).

daemon.stop() reports failure after succeeding

Bug · reproduced

This is the one failing test. AutonomousDaemon.stop() sends SIGTERM, then polls _pid_alive() until a timeout. But _pid_alive() uses os.kill(pid, 0), which succeeds for an un-reaped zombie, and start() discards its Popen handle — so when start and stop happen inside one process, nothing reaps the child and the poll never observes the death. The call spins the full timeout and returns False on a process that died instantly.

Normal CLI use masks this completely: autonomous start and autonomous stop are separate processes, and the daemon is reparented to init, which reaps it properly. The fix is to reap the child rather than to lengthen the timeout.

Reproduced A direct stop(timeout_seconds=5) returned False after exactly 5.0s; ps showed the process already gone and _pid_alive returned False immediately afterward. Fails as tests/test_daemon.py::test_start_and_stop_short_lived.

The heat gate runs on a hardcoded risk proxy

Accuracy

Gate 6 is only as good as the existing_risk figure it receives, and the live loop computes that as abs(qty) × price × 0.02 — a flat 2% stand-in for every open position, with a candid comment saying so ("lacking real stops post-hoc"). Real stops are chosen at entry and then not tracked, so portfolio heat is an estimate, not a measurement.

Exits show the same seam: they pass stop = price × 1.10, a placeholder whose only job is to satisfy gate 7's short-side check by construction. Neither is wrong as scaffolding, but neither should be mistaken for enforced risk.

Evidence monitor/live_loop.py — existing_risk accumulation in step(), and the SELL branch's stop=price * 1.10.

The lookahead guard is required by policy and called by nothing

Test gap

CLAUDE.md requires every new strategy to ship a lookahead-bias regression test, and the signal-generation skill points at a helper to do it with. That helper — no_lookahead_check() — has no call sites outside its own module. No test uses it. The one similarly-named test, test_ema_no_lookahead, checks an indicator directly.

The helper is also a heuristic (it compares signal correlation against current versus next-bar close, and its own docstring calls a positive result "suspicious, not necessarily proof") and it returns True when the expected column is absent — so a malformed frame passes silently. Six strategies are registered; none is guarded this way.

Evidence signals/generator.py:42 definition; grep for no_lookahead finds only the export, the skill doc, and an unrelated indicator test.

Documentation has drifted from the code in five places

Drift

Enough that a newcomer following the docs would write code that does not compile:

  • ARCHITECTURE.md's file layout lists execution/paper.py, execution/live.py and data/symbols.py — none exist — while omitting daemon.py, tune.py and execution/daily_budget.py.
  • CLAUDE.md names the guard no_lookahead(df); the real symbol is no_lookahead_check(df, signal_col="entry").
  • CLAUDE.md gives the strategy contract as generate_signals(self, df); the real signature requires a second argument, ctx: StrategyContext.
  • .claude/agents/risk-gate.md tells the agent to run tests/test_lookahead.py, which does not exist.
  • daily_budget.py's docstring says it reads orders.jsonl and fills.jsonl; it reads only the former.

The stated quality bars do not currently pass

Hygiene

CLAUDE.md sets ruff for lint and mypy --strict for typing. Neither is clean today, though nothing found is behavioural: 25 ruff findings, all hygiene (7 unused imports, 5 quoted annotations, 3 deprecated typing imports, 3 import-order, plus a few simplifications), 18 of them auto-fixable. mypy reports 17 errors across 8 files, mostly untyped typer callbacks in cli.py, with one genuine type conflict at cli.py:659 assigning a PaperBroker to a QuestradeBroker-annotated variable.

Coverage sits at 63%, but it is unevenly distributed in the least comfortable direction: live_loop.py — the module that actually trades — is the weakest at 31%, followed by pairs.py (41%), alerter.py (51%) and tune.py (54%). The router itself is well covered.

Note pytest needs uv sync --extra dev first; the checked-in environment has runtime deps but no test tooling, and a bare uv run pytest fails on a missing numpy rather than a missing pytest.

YAML outranks the environment, so the documented escape hatch is narrower than described

Subtlety

settings.py describes environment variables as an "escape hatch, useful in CI and one-off shells". Because YAML arrives as init kwargs, it wins over both env and .env — so that hatch only works for keys absent from trading.yaml. get_settings() is also lru_cached, meaning config is read once per process and a mid-session YAML edit does not reach a running daemon.

What is solidly built

Worth stating plainly, because the findings above are the exceptions rather than the texture:

  • The chokepoint holds. There is genuinely one path to a broker, and the layered confirmation design around it is thoughtful — a typed phrase for humans, an uncacheable env sentinel for machines, a filesystem veto for both.
  • Secrets are structurally unreachable from the configuration Claude manages, not merely discouraged.
  • Strategies are pure transforms. Six registered examples, each a DataFrame in and out, none holding a broker reference. The contract is the same in backtest, paper, and live.
  • Token handling is careful: encrypted at rest, atomically rewritten, one-shot refresh semantics honoured in a single code path — exactly as Questrade requires.
  • The sizer reports realized risk (shares × stop distance after flooring) rather than the requested budget, which is the honest number and the one the heat gate should see.
  • Rejections are fully explained. Gates accumulate reasons instead of short-circuiting, so a blocked order tells you everything wrong with it in one line of the journal.

Suggested order of work

Ordered by risk carried, not by effort. The first two close gaps between what the system promises and what it enforces.

  1. Wire KillSwitch.evaluate() into the loop — or delete its thresholdsCall it once per iteration in LiveMonitor.step() with equity, peak, and day-open. If automatic tripping is not wanted, remove the two settings and say in the docs that the switch is manual, so nobody relies on protection that is not running.
  2. Close the autonomous policy gap in the permission systemEither drop autonomous_enabled and autonomous_account from _TRADING_KNOB_FIELDS so only .env can set them, or narrow the allow rule from autonomous start:* to the exact no-argument form. Also fix the refusal message to name YAML.
  3. Reap the child in AutonomousDaemonKeep the Popen handle and waitpid it, or check for zombie status in _pid_alive(). Clears the failing test and makes stop() honest in-process.
  4. Track real stops instead of the 2% proxyPersist the stop chosen at entry in the journal and read it back for existing_risk, so the heat gate measures rather than estimates.
  5. Add the lookahead tests the docs already promiseOne per registered strategy, and make no_lookahead_check fail loudly on a missing column rather than returning True.
  6. Refresh the drifted docs and clear the lint backlogRegenerate ARCHITECTURE.md's file tree from the real layout, fix the three CLAUDE.md signatures, then ruff check --fix and annotate the typer callbacks.
